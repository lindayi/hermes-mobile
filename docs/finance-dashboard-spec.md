# Finance Observatory — implementation specification

Status: implementation authorized by user's dashboard request. This document is generic enough for public source control: never put actual balances, employer award quantities, account IDs, source IDs, names, addresses, screenshots or private records into public source/tests/issues. Runtime values come from the private SQLite database. Read-only analytics, not financial execution.

## Product and design

Primary surface MONITOR, secondary EXPLORE/INSPECT. Dense but calm desktop/tablet layout; mobile-first usability. URL /hermes/finance/ backed by frontend/finance/index.html and local CSS/ES modules. No hero, marketing cards, trackers, remote fonts or CDN scripts. Inherit legible app typography; deliberate tabular-number styling, charcoal/ink neutrals, teal income, amber spending, blue transfers, muted protected/unknown. Seven tabs: Overview, Cash flow, Transfers, Investments, Compensation, Obligations, Transactions & evidence. Sidebar on wide screens, compact scrollable tabs on narrow screens. 44px controls, keyboard focus, dark/light respecting system, reduced motion, accessible data tables beside charts.

Overview: dated recorded financial position by currency, personal/protected breakdown, cash and investments separately, obligations/liabilities where sourced. Never claim comprehensive net worth if home/car/current debt valuations are absent. Evidence coverage strip and unresolved items. Cash-flow Sankey/alluvial with stable columns, variable-width links, click-to-filter, signed reversals handled separately, supporting totals/table. Monthly income/net expense grouped bars and net-flow line. Allocation donut/treemap by account/registration/security. Single large focal chart rather than equal-card grid.

Cash flow: date range, currency, account, dataset and scope filters. External income, expense/recovery, investment activity, financing, transfer and unresolved shown distinctly. Expense hierarchy drilldown and monthly trend. Dates default to latest recorded year, not current empty year; clearly mark partial/incomplete coverage. Merchant/category details link to server-paged transactions. Stats are calculated from the same filtered predicate as drilldown. Never mix currencies. Household signed allocations from hierarchical view are authoritative; do not re-split partner receipts or double-count reimbursed expense.

Transfers: paired directional account network and searchable evidence list; count each cash link once, not sum absolute both legs. Distinguish card settlements, investment funding, own cash movements, in-kind migrations, same-account reversals, missing counterpart and protected-boundary movement. Date filter on debit/source event while show both endpoint dates to retain boundary-crossing matches. Links are neither income nor spending. Gross movement is explicitly a different metric.

Investments: latest recorded balances and coherent holdings, market vs book, gains, fees/income, non-overlapping monthly performance series, explicitly unknown cost and broker-book vs tax-ACB caveats. All account observations dated; old closed balances not resurrected. Reported account total includes cash: never add again. Do not sum overlapping return windows or present residual dollar gain as TWR/XIRR. Current-price estimates multiply last-known units by public quotes, with quantity date, quote timestamp/source/currency, fetch time, stale/error flags and unsupported coverage. No market-quote overwrite of ledger. GIC par and plan funds are not ETF shares. Unknown quote leaves historical value distinctly labelled, never counted as current estimate. Unvested valuation remains separate from owned portfolio/current cash.

Compensation: sample gross-to-net waterfall, current vs YTD clearly separated, employee RRSP/ESPP savings vs employer benefits, bank net already after payroll savings. Award timeline/staircase across stored exact dates and percentages; theoretical fractional quantities not claimed actual vested/net delivered. Public-price gross award estimate separate from grant reference value; no automatic scheduled-to-vested conversion when a date passes without actual evidence. No tax/net cash assumptions or implied guaranteed sale. Scenario stock-price multiplier can be UI-only labelled scenario, not persisted account valuation.

Obligations: property-tax schedule with bank-matched vs scheduled status, mortgage/HELOC current contextual observations and uncertainties from DB, registered-account notices/HBP/TFSA caution where documented. No invented future payment dates or principal/interest splits. List dated financial facts and coverage gaps if standardized values unavailable; absence is unavailable, not zero. No calendar, banking, tax filing or reminders mutation.

Transactions/evidence: bounded server search/pagination/filter; source ID/page and allowlisted Drive/Gmail evidence URLs; expandable transfer counterpart/category rationale/confidence. No raw document-text dumps, credentials, arbitrary filesystem reads/downloads, raw_json or whole DB export endpoint. Render strings as text, never injected HTML. Relevant detail is drilldown from all charts.

## Runtime and security

Integrate backend/finance.py router under /hermes/app-api/finance using existing AuthService.require_user followed by require_owner, default profile and ready status. Reuse existing passkey login, cookie, revocation/expiry semantics; no second auth store or bearer scheme. Require positive owner identity on every route BEFORE filesystem/DB/network work. Member, disabled, recovery, expired/revoked, missing session denied. Failed auth must clear rendered financial state. Shell may be public but contain no personal data. Login link to /hermes/, then return/retry finance (no arbitrary redirect).

DB path derived only from explicitly configured default profile root / finance / finance.sqlite3, resolved outside public roots; tests inject temp paths. No client path/SQL/table/provider URL. SQLite URI mode=ro, PRAGMA query_only=ON, explicit per-response read transaction; short-lived per-request connections, bounded timeout/progress handler/rows. Blocking SQL/network in sync handlers/thread pool, not event loop. Missing schema/database -> clean503 with no private path leak. No migrations at dashboard startup. No financial-data localStorage, IndexedDB, SW caches, logging, analytics, public assets or public test fixtures. Cache-Control:no-store, Vary:Cookie; no cross-origin CORS. Existing shared-origin trust is explicit. No native/WhatsApp/gateway changes. No new service workers.

Quotes: separate backend/finance_market.py. Fixed allowlisted HTTPS sources (Yahoo chart for public equity/ETF symbols, Bank of Canada Valet for USD/CAD); bounded timeouts/response sizes/symbol count; no redirects to arbitrary hosts. Only symbols are sent, not account/quantity/user data. Map a conservative supported set including MSFT and Canadian TSX ETF tickers with explicit .TO mapping; do not guess plan fund prices. Fixed short in-memory TTL, stale last-known response explicitly labelled on upstream failure, or unavailable if none. Validate finite positive price, currency and timestamp. Dates beyond credible clock bounds rejected. An unavailable/old provider does not yield fabricated live price. Refresh is bounded GET and no persistent financial writes.

## API contract v1

All responses JSON; money integer *_minor, explicit currency, ISO date/time; null means unknown. Money formatting preserves supported CAD/USD currency and rejects unknown or unsupported currencies rather than relabelling them. Global meta on responses: {generated_at,source:'sqlite',warnings:[]}. Filters: start/end ISO dates optional, currency CAD|USD (default CAD), scope personal|all|protected (default personal), account exact optional, category prefix optional, dataset bank|investment|all optional. Date range <=20years, bounded search length120, pagination limit1..100 offset0..100000. Scope personal excludes mother/family earmarks but exposes user protected cash as restricted; do not erase protected cash historically. Actual semantics must be described in response.

Drilldown precision amendment (review acceptance): `category_mode=prefix|exact` defaults to prefix for hierarchy search. Individual chart bands use exact category plus authoritative `flow` (income|expense|transfer|investment|financing|adjustment|unresolved). Category aggregates preserve effective flow, signed income_minor/expense_minor, source amount and count, so a mixed-flow category is never merged into a misleading expense band. record_id accepts the qualified analytical identifier or exact original tx_id/event_id; normal filters still apply. Linked transfer inspection visibly switches to the clicked endpoint date, currency and account with all scopes/datasets and clears conflicting category selectors. It is not silently constrained by the debit aggregate's date/account or family scope.

Compensation has independent `vesting_policy=horizon|range` (default horizon): grant references are not filtered by grant date to discover vest events. Full horizon exposes recorded future schedule; range uses vest dates and retains grant context for every displayed tranche. Payroll still follows its explicit pay-date/currency filters. Passing a date never establishes completed vesting.

GET /meta -> {meta,range:{start,end},accounts:[{account,allocation,planning_protected}],currencies,categories:[{category_id,label,parent_id}],coverage:{...}}.
GET /overview -> {meta,totals:[{currency,income_minor,expense_minor,net_minor,transfer_in_minor,transfer_out_minor,investment_minor,financing_minor,unresolved_minor}],monthly:[{month,currency,income_minor,expense_minor,net_minor}],categories:[{category_id,flow,income_minor,expense_minor,amount_minor,count}],balances:[...explicit safe fields from investment_latest_balances],bank_balances:[...if supported],liabilities:[...if supported],warnings:[...]}. Totals from same filtered hierarchical predicate. Label income minus expense as operating surplus, not all-cash change/net worth; return other categories separately. Initial bank/debt snapshot standardization may use dedicated read-only dashboard_positions if parent prepares it; never hardcode personal values.
GET /transactions -> {meta,items:[safe hierarchical fields],total,limit,offset}; query q searches description/merchant/category with parameterized LIKE escaped wildcard. Includes entry_id,record_id,account,date,description,component,category_id,amount_minor,currency,confidence,evidence,source_id,page,drive_url,allocation,current_planning_protected. Optional record_id filter for exact linkage. No raw document text.
GET /transfers -> {meta,items:[{link_id,link_type,evidence,debit:{record_id,account,date,amount_minor,currency},credit:{...},protected_boundary}],total,network:{nodes:[],links:[{source,target,amount_minor,currency,count}]},in_kind:[],reversals:[]}. Network aggregated per currency; pair counts once. Pagination items only; bounded complete aggregate distinct from page. Missing-side record explicit.
GET /investments -> {meta,balances:[],holdings:[],history:[],periods:[],realized:[],cashflows:[],warnings:[]}. Explicit safe field allowlists excluding raw_json. Include source fields. Bound history1000, periods1000, flows1000 with completeness/omission metadata, not silently truncated. Current holdings/balances coherent source view.
GET /compensation -> {meta,payroll:[],components:[],links:[],awards:[],vesting:[],warnings:[]}. Components and links belong to the displayed newest payroll reference only; coverage.selected_payroll_id makes that scope explicit. A component group above the response bound is withheld in full with incomplete coverage, and the UI must not draw a partial waterfall. Each link includes a nullable linked_record with the actual eligible endpoint record_id/date/account/currency/dataset; never infer its posting date from payroll. No raw_json; typed fields. If award symbol absent use a separately documented fixed MSFT symbol only for explicitly Microsoft employer, never all awards. Values come from DB.
GET /obligations -> {meta,tax_schedule:[],facts:[{fact_id,account,fact_name,value,evidence,source_id}],context:[],warnings:[]}. Facts bounded and select financial names/reviewers; JSON values parsed server-side, do not dump all arbitrary facts. Parent may prepare dashboard_notes table for source-backed narrative findings (no HTML). No invented mortgage amortization.
GET /quotes?symbols=MSFT,TGED.TO -> {meta,quotes:[{symbol,price,currency,as_of,fetched_at,source,status,stale,error}],fx:{pair:'USDCAD',rate,as_of,source,status}}. Max12 symbols, strict mapped allowlist, empty/errors gracefully represented. Frontend loads this independently so market failure cannot block ledger pages.

Frontend can tolerate unavailable optional arrays but must not substitute demo metrics. Charts expose a table alternative and filter interactions. Keep financial filters/route in memory or non-sensitive URL parameters only (no account data in analytics). Abort stale requests and fence late responses. Unknown, locked, unavailable, empty and error are distinct states. Revalidate on focus/page-show, clear data on401/403, clear hidden page data before bfcache restore. No endless polling.

## Source integration and release

Use canonical Hermes Mobile repository on fresh origin/main, dedicated task worktree. Public issue/spec contains architecture/schema and synthetic tests only. Disjoint writers: finance query/router, finance frontend, market provider, build/auth assembly and integration tests (parent). Use managed runner, observed TDD. No private DB/source/test evidence committed. Build preserves subdirectory index.html and fingerprints dependent finance JS/CSS; path validation/static deployment rules remain fail closed. No symlink to private state.

Mandatory security tests: anonymous/member/revoked/recovery/non-ready denial; read-only DB; no client SQL/path; injection/HTML text safe; missing schema safe; no-store; no cross-user cache; source URL validation; bounded query/network. Semantic tests: duplicate/pending exclusion by hierarchical source; split/recovery conservation; transfers not spending; currency/scope filtering; same predicates in drilldown; overlapping snapshots not summed; unknown basis preserved; future vesting not current holdings; quote failure/staleness/unsupported units; publication contains zero private rows.

Browser tests with synthetic fixtures: seven pages, filters, Sankey link drilldown, transaction pagination, transfer inspection, investment price failures, vesting chart,401 clearing, responsive390/768/1280 widths, keyboard, console/CSP errors, no persistent sensitive storage. Parent separately performs authorized read-only operational comparison against real DB without using it as public test fixture.

Finish through required exact-head hosted CI and genuine Copilot review, resolve findings, normal protected merge. Deploy only verified main with supported guarded bridge release; preserve all active runs, native listener, WhatsApp and services. A scheduled worker is not successful activation. If current chat itself prevents drain, disclose pending activation and use supported durable observation rather than kill/restart it. Verify public shell, anonymous API401, protected data with legitimate session only; physical owner passkey UI remains manual if no enrolled credential is available to the test browser.
