# Compact controls and per-turn model settings acceptance

1. Refresh, Search, New chat and similar unambiguous toolbar actions use the existing monochrome stroke family, with accessible names/tooltips and >=44px hit areas. Keep labels where meaning is ambiguous or destructive confirmation needs words; no blanket emoji conversion.
2. Read Inbox receipts have an × dismiss control at top-right, not a full-width/action-row text button. It retains the existing owner-bound dismissal API, busy/error/stale-view behavior. Unread receipts and pending approvals do not gain dismissal. Title/body reserve room; narrow/dark/light layouts remain usable.
3. Verify current sending/interrupt behavior before changing composer. Current bridge rejects new runs while a run is active/unresolved; existing native Stop is cooperative, not follow-up-message injection. For every active run, labelled red-outline Stop sits right-aligned in the live Activity/status heading, outside tool disclosure and away from model selection, with a minimum 44px touch target; it never submits the draft. The composer action is reserved for capability-gated steering or idle Send, not duplicate Stop. Queued/running/waiting approval can Stop; stopping shows disabled pending Stop; completed/failed/cancelled restores Send; unknown stays safely locked and must not imply a fresh send is safe. Sending before a run ID is known remains disabled, no accidental Stop/Send dispatch. Preserve draft, focus, late-response guards, retry identity and expanded editor.
4. Discover actual native model catalogue/request-overrides/reasoning support read-only, including credential/profile binding and route constraints. If supported, expose a compact per-conversation next-turn model/effort picker (e.g. existing model strip opens controls). Only allow actually advertised/configured profile-safe options; unsupported reasoning modes remain unavailable. Defaults inherit existing runtime behavior. The picker button shows the validated selected model (or validated catalogue default) with a dropdown chevron. It remains usable for the next turn while a known run is active, without changing that active run or adding model overrides to guidance. Freeze it only while an unresolved submission/retry still binds the model choice, not for the whole admitted run. Do not mutate shared global Hermes configuration/provider credentials or restart native services.
5. Execution options must be validated server-side, forwarded exactly once with new run, durably bound to idempotency identity and immutable once admitted. Retrying the same uncertain action must preserve its original model/effort; changing selection must not silently dispatch a different model under the same key. No arbitrary URL/key/provider escape hatch. Running turns cannot be retargeted. UI communicates selection for next turn versus observed recorded model; ownership/account/navigation cleanup stays fenced.
6. Write and observe failing tests before each code change; include real browser compact geometry and Stop lifecycle, backend auth/validation/dispatch/idempotency tests if execution options are added. No real model runs, user Inbox cleanup, account resets, configuration or live approval changes as tests. Keep canonical spec updated and verify final immutable generated assets under deployment conditions; deployment status and independent public verification must agree before claiming live success.
