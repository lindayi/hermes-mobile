# Finance money map

Issue #124; baseline 8d2a17a. The primary surface is Explore, secondary Inspect. This supersedes the Monitor-first composition in finance-dashboard-spec.md, not its financial/privacy rules.

## Experience

The overview is one large interactive money map: income streams enter from the left, accounts and evidenced movements live inside a central “Your accounts” realm, and expenses leave to the right. Internal transfers are not income or expenses. Investment activity stays inside the realm; financing, adjustments and unknown destinations remain clearly separate rather than being invented consumption. The graphic shows recorded aggregate movements, NOT tracing particular income dollars to subsequent purchases and NOT a balanced Sankey with fabricated opening/closing money. Unequal account inflows/outflows are expected. Line widths use a declared common amount scale; never imply balancing.

Quiet period/currency controls, secondary Filters disclosure, muted navigation, no KPI-card wall. Financial position, analytical tables and coverage remain accessible below/behind disclosures, not deleted. No live-price calls are needed for the main map. Existing seven sections remain usable. The default overview may bundle related category streams to avoid an unreadable wall of tiny paths. Bundles retain every constituent edge and its exact selector, preserve direction/kind/currency, and expose the full member list before record inspection; no silently omitted flows or fabricated aggregate-detail selectors. Verify realistic dense fixtures (roughly twenty accounts and one hundred categories), not just a five-node illustration. Wide layouts retain individual account nodes; a narrow overview may summarize them only with a visible “Expand your accounts” action and reversible expansion/focus. Paired transfers must still be visible as internal movements, never silently discarded or rendered as a zero-length path.

The viewport offers Zoom in/out, Fit diagram, wheel/pinch zoom and drag pan plus keyboard alternatives. Clicking a band opens a bounded, paginated detail inspector beside/over the map without replacing it. Closing or Escape retains viewport and filters; visible Back restores prior selection/filter/tab/viewport/scroll state; Overview returns to the unselected overview. History is bounded in memory only. Auth failure and hidden-page suspension clear financial data, details and private navigation state; history cannot resurrect cleared data. Late responses cannot paint over a newer selection or view. A denial from either parallel overview/map request clears private state independently of the other request's outcome, but a stale-generation denial cannot lock a newer view. Each successful reload reconciles focus and exact/group inspector selections with the current graph; an unavailable focus resets, changed values and members refresh, and removed selections close. Back preserves saved navigation intent, not stale monetary snapshots. Compact same-column links anchor to actual node bounds inside the account realm, and reciprocal/parallel streams must all be reachable by mouse and touch, not only keyboard.

## Read contract

GET /finance/flow uses existing Filters and owner-only read-only snapshot handling. Response:

- meta, range, currency, warnings, coverage
- nodes: [{id,label,kind,account?}], kind income|account|expense|investment|financing|adjustment|unresolved|transfer
- edges: [{id,source,target,kind,label,amount_minor,currency,count,selector}]
- selector: {endpoint:'transactions'|'transfers',filters:{...safe Filters}}

amount_minor is a nonnegative magnitude; direction follows actual source sign and is explicit in source/target and label. Never net refunds against gross spending inside a single unsigned band. Nodes/edges have stable IDs independent of row ordering. Category names come from category_nodes.label when available, else humanized category IDs, never allocation component='whole'. Metadata has one row per category.

External transaction edges group exact account/category/authoritative flow/direction. Include selector account, category, category_mode=exact, flow, direction=incoming|outgoing (amount_minor positive|negative), with date/currency/scope/dataset inherited by inspector. Investment activity uses account↔investment-category nodes inside the realm. Expense refunds/recoveries reverse the expense path and income reversals reverse income. Financing and unresolved activity stay separately labelled. No inference of source↔destination accounts from descriptions.

Paired transfer edges group debit account→credit account, link_type and currency, count cash_links once using existing source-date and either-endpoint membership semantics. Selector endpoint=transfers with source_account, target_account and link_type (new bounded exact Filters fields). Pair fields only constrain transfer queries; direction only constrains transactions. Missing/cross-currency counterparts must not be rendered as a normal matched pair. Unpaired transfer observations remain visibly identified as unmatched, excluding source-linked matched legs so money is not counted twice. Dataset/scope/date semantics and signed counterpart limitations remain explicit. No arbitrary row/sample-cap graph masquerading as the complete total; coverage exposes bounds and partial graph is clearly warned or withheld.

Existing APIs remain compatible. New filter fields are parameterized and length bounded. The additive transfer_status=matched|unmatched selector is retained by the inspector. An explicitly empty category is serialized when category_mode=exact; it must not disappear into an all-category request. Ordinary empty optional filters still mean no filter. Transaction queries use transfer_status to exclude evidenced matched legs, while pair queries use it to require or exclude normal matched pairs. This prevents an unmatched category edge from reopening its already-counted matched siblings. /flow uses the existing router authentication before DB access, same no-store and read transaction, finite query time and output bounds. No financial-data, market-provider or authentication mutations, public private-record exposure, credentials or persisted private browser state.
