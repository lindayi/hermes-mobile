## Auth owner (separate child)
Implement backend/auth.py, backend/auth_store.py (private auth SQLite), tests/test_auth*.py, tests/test_invite*.py and docs/tdd-auth.md.
Export AuthService(db_path, origin='https://lindayi.me', rp_id='lindayi.me', clock=time.time, bootstrap_secret=None) and build_auth_router(service) APIRouter with /auth/* /invites* /devices* /passkeys* /members* routes (prefix mounted by parent).
Export service.require_user(Request) dependency returns dict {id,role,profile,status,csrf_token,session_id,last_verified_at}. Validates cookie hashed server-side, expiry; app routes use this dependency. Export service.require_mutation(Request,user): enforce same Origin and X-CSRF-Token equals current session csrf. Sensitive endpoints step-up require fresh WebAuthn within 5min; never a debug header bypass.
GET /auth/me returns {user:{id,role,profile,status}, csrf_token}. POST /auth/logout. Passkey begin/finish routes: /auth/register/options POST {code,display_name}, /auth/register/verify POST {enrollment_id,credential}; /auth/login/options POST {}; /auth/login/verify POST {challenge_id,credential}. Real library verification. Begin with matching bootstrap registers owner/default only once; matching invite creates member with server profile member_<id>, status pending (profile provisioning by parent later; auth doesn't create Hermes profiles). Final verify sets cookie and returns me shape. Owner initially ready; pending members can use settings only, parent gates actual agent routes.
POST /auth/verify/options and /auth/verify/finish for session step-up (challenge/assertion same contract); GET/POST/DELETE /passkeys with separate add ceremony as needed; GET /devices, DELETE /devices/{id}. POST /auth/recovery/options POST /auth/recovery/verify (document exact contract if different, must not bypass WebAuthn), POST /auth/recovery/codes issues one-use codes only after step-up; use limited recovery sessions.
GET /invites {items:[...]}; POST /invites {label,expires_days:7} returns {code,invite:{...}} once; DELETE /invites/{id}. GET /members {items}; POST /members/{id}/disable. Own records only; user must be owner where appropriate. No storing raw secrets. Each code operation atomic/race safe. Rate limiting and security tests. Document route details for parent/frontend.

Push generic body by default with /hermes/?inbox=<id> link. No real notification send in tests.
