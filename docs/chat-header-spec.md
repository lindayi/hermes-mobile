# Compact conversation header acceptance

Replace the authenticated decorative logo banner and duplicate conversation heading with a single compact top row. Back to chats on left, truncated session title plus accessible Rename session icon centrally, textual/symbol status right. No decorative branding row on authenticated tabs. Preserve sign-in identity and existing navigation/security controls. Target 52–60 CSS px plus safe-area inset, 44px back/edit hit areas; no horizontal overflow at 320/390px, short landscape, desktop. Header remains outside message scroller; reduce empty message top space without damaging follow-bottom.

Rename uses existing authenticated PATCH /sessions/{id} title contract, not local-only label. Accessible focused dialog/input Save/Cancel/Escape, trimmed nonempty bounded title, wait for success; failures retain name/input and display useful error. Cancel makes no request. Late rename responses cannot alter another conversation or account; do not interrupt active run/stream or lose draft/scroll. Refresh/session inventory must show persisted title.

Status is meaningful and scoped to active conversation: connecting/loading, connected and idle after successful snapshot, sending, queued, running, waiting for approval, stopping, stopped/cancelled, failed, unknown/recovering, reconnecting/disconnected. Browser offline immediately indicates disconnected; online alone is not proof of server recovery. Valid current-view requests/events restore transport status. Idle connection should be checked with bounded read-only requests (no model action), with timers/listeners cleaned up on navigation/signout. Transport failure must not be overwritten by old requests/events; unknown remains unknown and cannot enable unsafe retry. Poll freshness applies to terminal responses too: a delayed unknown/completed/failed read from before a newer approval event must neither change header status nor close the active stream; a subsequent fresh authoritative terminal read must still finish normally. Color is supplemental to text; role=status polite announcements only on meaningful transitions. No duplicate big status row beneath header.

Real Chromium must exercise generated versioned assets, not source-only fixtures. Full regression suite and independent scoped review precede frontend-only deployment.
