# Owner next-turn controls contract

`GET /hermes/app-api/sessions/{id}/model-options` is authenticated and session/profile checked. It returns `{available,models:[{id,provider,label,reasoning_efforts}],default:{model,provider}}`; unavailable returns false, empty models and null default. The application exposes this catalog only for the owner/default profile connected to the independently verified owner listener. That listener advertises the capability only when its model-options route and explicit-model execution lock are installed. Family profiles remain unavailable.

The owner listener builds its configured Copilot model list through Hermes inventory and credential resolution. It reads exact `capabilities.supports.reasoning_effort` values from the authenticated model catalog and intersects them with efforts accepted by the pinned `/v1/runs` transport: `none`, `minimal`, `low`, `medium`, `high`, and `xhigh`. It does not infer support from model IDs or a boolean capability. `max` is omitted because the pinned runtime's model-effort resolver and mobile transport do not accept it as a verified model-specific wire value. If the authenticated-only catalog read fails, controls are unavailable. The capability read never retries anonymously or clears the shared native catalog cache. Credentials stay inside the native owner process.

The pinned native `/v1/runs` transport does not enforce Copilot CLI context tiers. Therefore this app does not expose a Context control or pass a cosmetic context override. CLI-wide `default` and `long_context` values do not prove model-specific or app-transport support. Existing context and compression behavior remains unchanged.

`POST /hermes/app-api/runs` accepts optional `selection:{model,provider,reasoning_effort?}`. Default omits selection; Default effort omits `reasoning_effort`. Unknown fields, unsupported model/provider/effort combinations are rejected before dispatch. The native run adapter revalidates an explicit effort in an awaited worker thread before native admission. An immutable request-local context binds the result to the background run; agent creation does no catalog I/O. Exact per-agent transport wrapping applies the validated effort after the registered Copilot profile builds the chat-completions or Responses payload. An unsupported or changed model fails instead of clamping to another effort. Default selections keep the pinned runtime's existing reasoning behavior. The selection is part of durable idempotency identity; the same key with changed selection conflicts, including unresolved retries. Uncertain Retry uses the original body and key without a second native dispatch.

An explicit model is passed to the native agent with fallback locked for that run. It either uses the requested model or returns a clear failure; it must not silently run another model. Runs without an explicit selection keep existing default and fallback behavior. The UI describes the control as a requested next-turn model, not observed execution. Observed model information comes only from trusted runtime data; generated text is not identity evidence.

Each options read and selected admission verifies the fixed owner home and loopback URL, reviewed launcher and native API source SHA-256, owner service-manager MainPID, process UID/command/cwd, and ownership of the exact loopback listening socket. A changed launcher/native implementation fails closed until reviewed. The OS account and service manager are trusted; this is not a sandbox against a compromised same-UID process. Probe behavior is injectable in tests. Native `/v1/models` must advertise only the virtual `hermes-agent`; route aliases are rejected. Family controls remain unavailable. Runtime replacement after verification is an OS-level TOCTOU boundary, not an adversarial runtime-attestation guarantee.

The requested next-turn model and effort are device-local preferences scoped by account and session, retained across app-window closure in localStorage. Legacy tab-local selections migrate without overriding newer persistent choices. Explicit Default clears the override durably; unavailable saved selections block new submission until validated or explicitly corrected. Sign-out clears owner-local preferences and verified deletion clears only that session's preference; this is not cross-device synchronization or evidence of prior model execution.

The UI hides and disables controls if the catalog is unavailable or the read fails. It snapshots selection into each new submission identity and never changes the body on retry. Capabilities and model-specific effort choices are revalidated before each new admission. Default submissions preserve their legacy upstream payload.
