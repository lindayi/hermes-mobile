# Owner next-turn controls contract

Implementation target (not a deployment claim): `GET /hermes/app-api/sessions/{id}/model-options`, authenticated and session/profile checked, returns `{available,models:[{id,provider,label,reasoning_efforts:[]}],default:{model,provider}}`. Unavailable returns false, empty models and null default. Only owner/default profile bound to the independently running owner listener may expose controls. Current configured authenticated non-synthetic provider only. Family remains unavailable.

`POST /hermes/app-api/runs` accepts optional `selection:{model,provider,reasoning_effort?}`. Default omits selection; Default effort omits reasoning_effort. Unknown fields, unsupported models/providers/efforts are rejected. Selection is part of durable idempotency identity; same key with changed selection conflicts, including unresolved retries. No automatic native redispatch.

Label **Requested model / next turn**, not guaranteed effective model: native fallback remains possible. Keep observed transcript model distinct. The actual owner service is `hermes-mobile-api.service`, active PID verified read-only, invoking `backend/native_api_service.py`. This constructs APIServerAdapter directly with host/port/key only, no model routes and no GatewayRunner. `_session_model_override_for` returns None without GatewayRunner; gateway messaging process is separate. Explicit Runs model/provider is therefore honored as requested selection before fallback.

Reasoning remains **Default only** for this slice. Source `hermes_cli/models.py:3823–3872` stores exact Copilot catalog in process-local memory (five-minute monotonic TTL, keyed by credential), not a profile-bound disk catalog exposed to the bridge. The disk provider_models_cache stores IDs, not exact supports.reasoning_effort arrays. No token extraction or direct provider request is permitted. Boolean reasoning hints are not effort authorization.

Deployment trust boundary: each options read/new selected admission verifies fixed owner home and loopback URL, reviewed launcher and native API source SHA-256, the owner service manager's MainPID, process UID/command/cwd, and ownership of the exact loopback listening socket. A changed launcher/native implementation fails closed until deliberately reviewed. The OS account/service manager are trusted; this is not a sandbox against a compromised same-UID process. Probe is injectable in tests. Native `/v1/models` must advertise only the virtual `hermes-agent`, rejecting route aliases; capabilities and current authenticated Copilot catalog are read fresh. Family controls remain unavailable. Source/runtime replacement after verification is an OS-level TOCTOU boundary, not an adversarial runtime-attestation guarantee.

UI must hide/disable picker on unavailable or GET failure. Snapshot selection into uncertain submission identity; never rekey or change its body on retry. Capability and catalog must be revalidated before each new admission. Existing/default submissions preserve their legacy upstream payload.
