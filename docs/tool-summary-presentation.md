# Tool presentation contract

## Sources inspected (installed native source, not live account data)

- `/usr/local/lib/hermes-agent/gateway/platforms/whatsapp_cloud.py`: WhatsAppCloudAdapter inherits WhatsAppBehaviorMixin and BasePlatformAdapter. The shared WhatsApp mixin does not supply a tool preview override.
- `gateway/platforms/base.py`, `BasePlatformAdapter.format_tool_event` / `format_tool_preview` (around lines 3337–3393): ordinary all/new mode shows tool plus a compact primary-argument preview (default 40 characters), unlike verbose mode's JSON arguments.
- `agent/display.py`, `build_tool_preview` / `prepare_tool_preview` (around lines 446–624): primary argument selection and platform formatting; native may also preview commands/code/goals. Mobile deliberately implements a narrower independent allowlist, rather than importing the native runtime or recreating verbose mode. Native browser text redaction remains untouched.
- `gateway/platforms/api_server.py`, run progress callback (around lines 6598–6616): `tool.started` includes tool and preview; completion includes duration and boolean error. This native callback currently provides no call ID, but mobile preserves IDs whenever supplied by an upstream version.
- `hermes_state_common.py`, messages schema (around lines 320–344): public `content`, tool fields, and `display_kind`/`display_metadata` coexist with private reasoning and API fields. No explicit commentary channel exists in this inspected schema, and no documented commentary display_kind was found in source. Mobile does not infer commentary from text or tool adjacency and does not select reasoning, reasoning_content, reasoning_details, codex items, or api_content. No reasoning stream is newly forwarded.

## Saved display history

`NativeCatalog.messages` adds `summary` to valid assistant function calls and to tool result display rows. Summaries match `tool_call_id`, including assistant calls before the requested/latest page. The lookup remains scoped to session and visible rows. Missing matches fall back to tool name. This is read-only presentation; native execution/resume context and SQLite bytes are unchanged. Existing arguments and result `content` remain in the API for backwards compatibility; the UI must render summary, not raw arguments/results, as its tool detail.

Backend summaries are one line of at most 360 characters including the tool name; frontend details are also bounded at 360 after privacy screening. Allowlisted context includes paths, queries, read offset/limit, search target/glob, skill reference file, safe simple terminal command/workdir/background mode, process action/ID/wait timeout, browser action/ref, and bounded parallel child names or delegation goals. Code execution uses static labels, never code. Typed text, stdin, patch bodies and arbitrary arguments stay omitted. The functions. namespace is normalized for display. Both expanded rows and folded bars retain canonical tool identity and recorded duration (seconds), without inventing missing data or success. Frontend legacy fallback may show a screened public output/content/text/message string, never an object dump. No LLM is called.

The additional conservative guard strips HTTP(S) URL userinfo, query and fragment; screens percent-decoded text for sensitive labels, recognizable key prefixes and long opaque strings; rejects JSON/shell punctuation, control/non-ASCII text and oversized values. Secret-bearing or ambiguous details are omitted, not partially invented. Some harmless strings are intentionally omitted. This is a presentation minimization layer, not a guarantee that arbitrary natural-language secrets can be detected; native redaction is neither disabled nor replaced. Do not expand to arbitrary argument values or render raw payloads as a fallback.

## Live display events

Orchestrator normalizes only its tool-event forwarding branch. The journal receives allowlisted lifecycle fields (`event`, tool/name aliases, run/call IDs, status, error/is_error, duration), plus sanitized `summary` on `tool.started`. It drops raw preview, args, arguments, results, output and other payloads. The same allowlisted tool semantics apply to native previews, including screened simple terminal commands and known process/browser preview shapes. Completion has no new summary: the UI keeps the started summary rather than replacing it with a tool-only label. Existing lifecycle error metadata is preserved; it is not used as summary text.

Journal event projections add `observed_at` from the durable receipt row, not the replay wall clock or a payload claim. SSE and snapshot replay expose the same receipt time. Materialized journal history preserves each tool start/progress boundary and keeps completion duration without moving the start; background cards use those segment boundaries within their originating turn. Missing historical times are labeled approximate.
