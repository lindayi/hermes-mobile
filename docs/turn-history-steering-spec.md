# Turn history, public progress and steering investigation

Acceptance written before implementation for the current user correction.

1. Conversation initial/latest and Load older requests use genuine user→assistant turn boundaries, not arbitrary100-row cuts. Extending a page backwards must keep its original exclusive upper boundary so consecutive pages neither omit nor overlap rows. Native delegation-completion envelopes rendered as tools are not user-turn boundaries. Return actual offset. Preserve chronology, newest-on-open, scroll anchor and compact tool pairing. Explicitly bound pathological oversized turns with a truthful continuation indicator rather than silently claiming complete turns.
2. Consecutive tools within the same loaded sequence coalesce even at a legacy/capped page seam; never join across a real user message or public assistant commentary. No lost result details, repeated call/result rows or collapsed state regressions. Existing native compaction/journal overlay rules remain.
3. Ongoing status must not use an ellipsis that resembles More. Use a recognizable ring progress indicator with an accessible Running label (clock for Queued); semantic colors and outcome labels remain. Respect reduced motion. Verify conversation list and activity/header instances, mobile light/dark.
4. Trace intermediate PUBLIC assistant commentary from native callbacks through journal/SSE and saved history. Public commentary is readable in chronological position rather than mistaken for private reasoning or swallowed into final output. Never expose reasoning.available/private analysis or invent text the runtime did not emit. If the missing source is in the native runtime, document exact evidence and deployment prerequisite rather than claim frontend changes recovered it.
5. Steering is investigation-first in this iteration: inspect actual native schema, safe delivery points, lifecycle, durable acknowledgement/idempotency, cancellation/approval interactions and history. No steering into real active tasks as a probe. Enabling requires owned profile/run binding, CSRF, exact-once-or-honest-unknown handling, preserved draft and chronology. Do not merely unlock ordinary Send, which currently starts a new run. If supported safely, proposed UI retains a clearly labeled Send steering action with separate Stop and model changes apply only to the next turn, with the picker enabled during admitted runs and locked only for pending/uncertain submissions. Current UX correction supersedes the earlier placement restriction: right-align a labelled red-outline Stop in the live Activity/status header, outside disclosure and away from model selection, for all active runs. Steering remains capability-gated and uses plain contextual guidance rather than checkpoint jargon.
6. Observe RED→GREEN for changes; real SQLite paging and browser seam/geometry tests, source-only private-content exclusion, independent review, frozen generated full pipeline and guarded publication. Canonical spec updated in place. No owner enrollment reset, native/gateway/cron restart, production test model run or real user-history mutation.
