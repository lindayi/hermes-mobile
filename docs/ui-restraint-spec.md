# Restrained UI and informative tool activity

Latest user acceptance supersedes the earlier blanket emoji requirement and unknown-telemetry placeholders.

1. Toolbars and mechanical actions (back, edit, send, expand, copy, stop, disclosure) use consistent small monochrome symbols, accessible labels and >=44px touch targets. Avoid decorative emoji in dense status/tool rows. Bottom navigation stays legible and coherent with restrained symbols. Use neutral surfaces, one accent for selected/primary actions, no ornamental badges.
2. Conversation filter is a compact text-only segmented selector (Chats, All, Cron, Tests), not a full-width form label/select stack. Search starts collapsed behind a labelled 44px search icon beside the filter, opens with input focus, and stays expanded for active queries. Close/Escape clears search and paging with focus returned to the toggle. Preserve pagination reset, selection, back navigation and account reset. Remove repeated decorative session chat icons without removing actual run status. Small screens fit without horizontal overflow.
3. Chat header background/border extends to both edges of the app content area, including mobile viewport; controls retain internal safe-area padding. Message reading width may stay constrained on desktop. Long titles, status, rename target and composer must remain usable at 320px, landscape and desktop.
4. Telemetry omits unknown model/provider/context fields entirely, including expanded details. Known model alone remains useful; wholly unavailable telemetry does not leave an empty strip/disclosure. Known usage may be shown accurately without inventing capacity/percentage; no unknown timestamp/source placeholder rows. Session lifetime totals are never labeled context occupancy.
5. Each expanded tool entry shows grounded useful detail when any exists: sanitized meaningful summary, bounded command/path/query/goal/arguments, or bounded available result. Prefer useful command text over a repeated bare tool name. Display explicit 'Arguments/output not recorded' only if genuinely no data exists. Preserve saved/live equivalence, tool identity and folded defaults, bounded text, escaping and existing secret/private-reasoning protections. Never fabricate missing results or expose arbitrary raw credentials/config.
6. Tests first with observed RED/GREEN: icon semantics, conditional telemetry (partial/all-null/error), filters lifecycle, full-width actual browser geometry, expanded saved/live tool examples including nested wrappers, truncated input and sensitive values. Inspect real mobile light/dark screenshots.
7. Keep canonical specification current, independently review frozen changes, run full staged generated-asset checks and deploy only affected services. Frontend-only publication if backend remains unchanged; otherwise idle-guarded full release with outcome receipt. Never present scheduled release as live.
